# Field Rosters

現場配置表のReact / TypeScriptアプリです。実装元は`source`ブランチ、公開用のビルド成果物は`main`ブランチで管理されています。

## 開発と検証

```sh
npm ci
npm run dev
npm run typecheck
npm test
npm run build
```

`npm test`は日本時間の日付境界、月末・年末・うるう年、カレンダー、氏名が同じ人員、休み・未配置の判定を検証します。

ブラウザテストはPlaywrightとMicrosoft Edgeを利用します。Playwrightを利用できる環境で次を実行してください。別のインストール済みブラウザを使う場合は`BROWSER_CHANNEL`を設定できます。

```sh
node tests/paidLeave.browser.cjs
```

テストはFirebaseを`tests/mocks/`に差し替えます。本番Firebaseには接続せず、登録・取消・重複防止・複数タブ共有・保存エラー・配置編集の保持・完了前確認・モバイル幅を検証します。画面画像は`test-results/`へ保存します。

## 有給休暇

- ホーム、設定、人員配置の「有給休暇」ボタンから開けます。パスワード入力は不要です。
- 日付・曜日を左、登録済みの氏名を右に並べた一覧です。上下スクロールで前後の日付へ移動し、月をまたぐと日付を自動で追加します。「今日」で当日に戻れます。
- 日付をタップすると氏名だけの人員一覧から登録できます。検索欄や役職の表示はありません。登録済みの氏名をタップすると取消を確認します。同じ人員・日付の重複登録はできません。
- 登録は既存の人員IDと日本時間の日付で管理します。配置表の更新日時は変更しません。
- 配置編集中も有給の更新を受信します。対象日の有給者を一覧・札・人員操作画面に表示し、現場に配置された有給者がいる場合は配置完了前に注意確認を出します。
- 確認日は**配置完了時に記録する更新日時の翌日（日本時間）**です。編集中は現在時刻から予告し、完了直前に再計算します。日付が変わった場合は改めて確認します。
- 接続できない場合は保存済みの表示であることを明示し、登録・取消を無効にします。配置完了時にも最新情報を確認できていないことを表示します。

ホームの管理者認証・解除は黄色の閉じた鍵／赤色の開いた鍵、LINE通知はメガホン、設定は歯車のアイコンで表示します。同期状況の表示と検索ボタンはホームから除いています。一括表示はPC・タブレットのみ表示し、iPhoneでは表示しません。

## 共有データと公開

有給はFirestoreの`app_data/shared_paid_leaves`ドキュメント内の`entries`マップに保存します。キーは`人員ID_YYYY-MM-DD`です。登録は該当キーのマージ、取消は該当フィールドだけの削除で行うため、別の人員・日付の更新を上書きしません。配置表とは別ドキュメントなので、旧バージョンの画面による配置表更新でも有給データが消えません。

`firestore.rules`は提供された現在の配置表用ルールに、有給ドキュメントの読み取り・作成・更新の許可を追加したものです。登録・取消にパスワードやログインは不要です。ドキュメント全体の削除は許可せず、取消は該当する登録フィールドだけを削除します。公開時はFirebase ConsoleのFirestore Database →「ルール」にこのファイルの内容を反映して「公開」してください。Firebaseルールはこのリポジトリから自動配備されません。

Firebase CLIで公開する場合は、対象プロジェクトの権限があるアカウントでログインし、次を実行します。`firebase.json`はFirestoreルールだけを設定しています。

```sh
firebase deploy --only firestore:rules --project field-rosters-pro
```

既存の配置表のJSONバックアップには、有給の独立した共有ドキュメントは含まれません。配置表の復元・インポートは有給データを変更しません。

`source`への変更を取り込んだ後、`npm run build`で生成した`dist/`を既存の公開手順で`main`へ反映してください。ソースへのPR作成だけでは公開中のアプリは更新されません。
